## המוצר

**FOUR COLOR** — פלאגין Multiband Color/Saturation ב־JUCE 9 / C++20, VST3 + AU + Standalone.
יורש רוחני לרעיון של QuadraFuzz, לא העתק. ארבעה בנדים, ארבעה מנועי צבע, ציר Behavior דינמי לכל בנד, ו־Harmonic Space שמפזר **רק** את התוצר הלא־ליניארי.

מסלול האודיו:

```
Input Trim → 4-band crossover (LR4 tree + allpass compensation)
  → לכל בנד: BehaviorDetector → pre-Tone → Oversampled ColorEngine → post-Tone
             → HarmonicSpace (residual only) → BandMix / Level / Solo / Mute / Bypass
  → סכימה → Global Tone (tilt) → AutoLevel → יישור latency → Dry/Wet
  → Output Trim → Safety
```

**מצב נוכחי:** שלב 70% הושלם ואומת, ואחריו הממשק נבנה מחדש מאפס לפי תמונת Reference (4 commits: design system / layout / analyzer+interaction / wiring+QA).
**304 בדיקות אוטומטיות עוברות, 0 נכשלות. auval עובר. VST3 + AU + Standalone נבנים.**

## מה כבר נמדד ומאומת — אל תגלה את זה מחדש

| נושא | מדידה |
| --- | --- |
| Crossover recombination | שטוח עד **0.0001 dB** (30 Hz–18 kHz, כולל נקודות החיתוך) |
| Null מול AP(f1)·AP(f2)·AP(f3) | **-111.9 dB** worst sample, **-109 dB** RMS — רצפת float32 |
| הבדל בין ארבעת המנועים | מרחק log-spectral בין זוגות **8.6–26.4 dB** |
| פיצוי עוצמה סטטי | כל המנועים בתוך **±2.5 dB** לאורך כל טווח ה־Drive |
| Aliasing — FUZZ drive 85, worst case | 1x **-19.7** / 2x **-25.1** / 4x **-42.1** / 8x **-60.4 dB** |
| Aliasing — BITE drive 60, חומר טיפוסי, 4x | **-70.1 dB** |
| Latency | 0 / 49 / 60 / 65 samples ב־1x/2x/4x/8x @48k; wet מרופד ל־ceil(L) ב־Thiran |
| Global bypass | קלט מושהה בדיוק ב־latency המדווח (שגיאה < 1e-5) |
| Mix 50% | שטוח עד **0.13 dB** — הרגל היבשה היא ה־allpass reference של ה־crossover |
| BODY↔ATTACK | **1.98 dB** הפרש crunch על המכה (אנרגיית נגזרת), מונוטוני; חומר מתמשך זז < 0.6 dB |
| Space | יחס halo hot/quiet **9.6×**; ההילה נעלמת 300 ms אחרי עצירת המקור; בנד נמוך מונו bit-exact; correlation 0.90 |
| Auto Level | שגיאת עוצמה על FUZZ חם: **1.49 → 0.07 dB**; ה־gain מוחזק בשקט |
| CPU — DSP | **20.2× realtime** ב־4x, **13.5×** ב־8x (סטריאו, ארבעה מנועים + behavior + space) |
| CPU — Analyzer | **12.5%** מליבה אחת; ריענון מלא של כל הממשק **27.1%** |
| הקצאות ב־audio thread | **0** — מוכח ע"י החלפת `operator new` גלובלי |

**החלטות סגורות — אל תפתח מחדש בלי טיעון מספרי:**

- ה־crossover הוא עץ LR4 עם **פיצוי allpass של האח** — שטוח לפי בנייה, לא לפי כיול.
- ארבעת המנועים הם **ארבעה מבנים שונים**, לא `tanh()` עם קבועים:
  WARM רציונלי + sag + bias · IRON טנגנס היפרבולי בתוך **לולאת פידבק** עם one-pole "core loss" · BITE זוג דיודות אקספוננציאלי אסימטרי עם de-emphasis חלקי (~50%) · FUZZ יישור חלקי + fold כפול + gate לפי מעטפת הכניסה.
- ה־crossfade בין צבעים רץ **בתוך הדומיין המודגם־יתר**.
- ה־residual ב־Space מוערך ב־**least squares עם שני בסיסים** (clean + HP(clean)); fit סקלרי השאיר 37% מהמקור בתוך ה"residual".
- Behavior: עומק ±9 dB, גלאי כפול־מעטפת, זמנים משתנים לפי בנד, stereo-linked.

## מה שבור או פתוח — הרשימה המלאה, כדי שלא תבזבז את התשובה על גילויים

1. **Windows מעולם לא הודר.** המוצר מכוון ל־Cubase 15 / Windows; כל הפיתוח על macOS. אין CI.
2. **אין Cubase על מכונת הפיתוח** — אין אימות scan, אוטומציה או state recall בהוסט אמיתי.
3. **pluginval לא מותקן** (חינמי; לא הותקן ללא אישור).
4. קיפול half-band ליד Nyquist: תוכן מעל 24 kHz מתקפל ל־~23.1 kHz ב־-29.9 dB בכל גורם oversampling. מעל תחום השמיעה, מתועד.
5. Draft 1x עם aliasing נשמע (-19.7 dB worst case).
6. **ויזואליזציית ה־residual לא מחוברת** — `Analyzer::setResidualProvider()` הוא seam ריק. ה־Reference רומז על שכבת קונטור הרמוני שנייה; לא ציירנו נתונים שלא נמדדו.
7. Auto Level משתמש בפרוקסי עוצמה **RMS, לא K-weighted**.
8. **ADAA לא ממומש**; קיים רק seam.
9. A/B לא נשמר ב־state של הפלאגין (מכוון).
10. 27 פריסטים בלבד; יש תפריט קטגוריות, אין preset browser מלא.
11. הפונט Inter לא מצורף — נעשה שימוש בפונט המערכת עם אותה משמעת tracking.
12. אין Installer, אין רישוי, אין הפצה.

## מה אני צריך ממך

תעדוף מנומק ל־**30% האחרונים**, בהנחה שהמטרה היא **מוצר שנמכר**, ושהמכשול הגדול ביותר הוא שהפלטפורמה המסחרית (Windows/Cubase) לא הוכחה.

ענה על אלה במפורש:

1. **סדר הביצוע.** מה חייב לקרות ראשון ולמה. האם אימות Windows/Cubase קודם לכל ליטוש DSP?
2. **איכות ה־DSP.** קרא את `ColorEngine.cpp`. האם ארבעת המנועים באמת מספיק שונים *מוזיקלית*, או שהמדידה (מרחק log-spectral) מסתירה דמיון? מה תשנה בכל מנוע — ספציפית?
3. **ADAA.** שווה את הסיכון בשלב הזה, בהתחשב ב־-42 dB ב־4x ו־-60 dB ב־8x? אם כן — באיזה מנוע קודם?
4. **Auto Level.** המעבר ל־K-weighting מוצדק, או ש־0.07 dB שגיאה אומר שזה בזבוז?
5. **Behavior.** ±9 dB ו־3 ms החלקה — הכיול הנכון לחומר אמיתי, או שהבדיקה (רכבת קיקים סינתטית) מודדת את הדבר הלא נכון?
6. **Harmonic Space.** ה־fit בשני בסיסים מספיק, או שיש מקרה שבו הוא יקרוס (למשל FUZZ עם gate פעיל)? מה הבדיקה שתחשוף את זה?
7. **שכבת ה־residual בממשק.** מה בדיוק צריך `HarmonicSpace` לחשוף ל־GUI כדי שהציור יהיה מדידה אמיתית ולא קישוט — ובאיזה מחיר CPU?
8. **מה בארכיטקטורה יחסום שחרור מסחרי** ולא יהיה זול לתקן בעוד חודשיים.
9. **מה מיותר** — אם משהו ברשימה שלי לא שווה את הזמן, אמור זאת.
